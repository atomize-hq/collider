## What "landing a loop" means

Adapting one ai-elements registry entry into the collider repo end-to-end. Every loop touches:

1. `src/components/ai-elements/<name>.tsx` (and split siblings if > 200 LOC)
2. `src/components/ai-elements/<name>.stories.tsx`
3. `storybook/component-specs/<name>.json`
4. `storybook/story-inventory.json` (append entry)
5. `storybook/story-inventory-contract.test.ts` (append entry — loop order)
6. `storybook/proof-structure-contract.test.ts` (insert entry — **alphabetical** order)
7. `storybook/reusable-component-promotion-contract.test.ts` (insert in TWO lists — one loop-order, one alphabetical)
8. `artifacts/storybook/proof-coverage.json` (auto-regenerated by `pnpm govern:storybook-proof`)
9. `docs/ai-elements-inventory.md` (bump counts + move component from queue to done)
10. A Figma component on the canonical file, wired back via `figmaComponentRef` in the spec

Result: two commits — `feat(ai-elements): seed X through Stage-2 loop` and `docs: bump ai-elements inventory to N/48 (X done)`.

## The 7-step recipe

Run in order. Do NOT batch; each step's output informs the next.

### 1. Registry probe (2 min)

```bash
# Fetch the registry entry — the source-of-truth for source, deps, registryDeps
curl -s https://elements.ai-sdk.dev/api/registry/<name>.json
```

Read: `dependencies` (npm), `registryDependencies` (shadcn ui prims), `files[0].content` (source), `files[0].target` (final path in-repo, e.g. `components/ai-elements/<name>.tsx`).

**Sanity check:** does anything in `dependencies` NOT already exist in the repo's `package.json`? Does anything in `registryDependencies` NOT already exist in `src/components/ui/`? If yes, front-load the install:

```bash
pnpm dlx shadcn@latest add <prim>          # for shadcn ui prims
pnpm add <npm-package>                     # for npm deps
```

The current inventory queue's "New deps this loop" column already tells you what to expect for loops 24–32 — trust it but verify by probing.

### 2. Land the code (5–10 min)

Adapt the vendor source into `src/components/ai-elements/<name>.tsx`:

- Rewrite imports: `@/registry/default/ui/<prim>` → `@/components/ui/<prim>`
- Rewrite sibling imports: `./<sibling>` stays the same
- Prettier: single quotes, trailing commas, 2-space indent (preflight will auto-flag violations)

**LOC caps (enforced by `just loc`):**

- TSX: max 200 lines per file
- TS: max 300 lines per file
- Rust: max 400 lines per file

If vendor is over the TSX cap, split by concept. The established pattern from attachments/queue/package-info:

- `<name>.tsx` = root + context + core parts
- `<name>-parts.tsx` = the compose-your-own extras
- `export * from './<name>-parts'` at the END of `<name>.tsx` (barrel re-export)

Consumers keep one import path (`from './<name>'`).

### 3. Write the stories (10 min)

**Tier decision:** the spec has one of two shapes.

| Component character                                                 | Tier        | Required story kinds                                                 |
| ------------------------------------------------------------------- | ----------- | -------------------------------------------------------------------- |
| Pure display (no button, no expand, no state)                       | primitive   | `default, variant-matrix, docs` (3)                                  |
| Display with an interactive Button (click handler, focus, keyboard) | primitive   | `default, variant-matrix, actions, keyboard, focus, docs` (6)        |
| Compound with expand/collapse, state gating, complex interaction    | interactive | `default, state-matrix, keyboard, focus, workflow, motion, docs` (7) |

Look at a comparable existing spec to copy the pattern:

- Pure display 3-kind: [image](../storybook/component-specs/image.json), [message](../storybook/component-specs/message.json), [package-info](../storybook/component-specs/package-info.json)
- Interactive-button 6-kind: [suggestion](../storybook/component-specs/suggestion.json), [snippet](../storybook/component-specs/snippet.json), [checkpoint](../storybook/component-specs/checkpoint.json)
- Compound-interactive 7-kind: [plan](../storybook/component-specs/plan.json), [chain-of-thought](../storybook/component-specs/chain-of-thought.json), [agent](../storybook/component-specs/agent.json), [queue](../storybook/component-specs/queue.json)

**Story patterns to reuse:**

- **Callback stubs:** module-scoped `const onFoo = fn()` at the top; `render: () => <Demo onFoo={onFoo} />`; `play: async ({ canvasElement }) => { onFoo.mockClear(); ... }`. Do NOT use `args: { onFoo: fn() }` on `StoryObj<typeof meta>` — TS rejects props not on `meta.component`.
- **Tooltip stories:** wrap the Demo in `<TooltipProvider>` from `@/components/ui/tooltip`. Radix requires an ancestor provider; the Storybook harness doesn't provide one globally.
- **Meta.args required when the component has required props:** if `component: Foo` and `Foo` has any required props, set `args: { requiredProp: 'value' }` on meta so all `StoryObj<typeof meta>` entries typecheck.
- **Interactive tier state assertions:** Radix Collapsible/Accordion triggers have `role="button"` and `data-state="open"|"closed"` — use `await expect(trigger).toHaveAttribute('data-state', 'open')` for expand/collapse flows.

### 4. Governance surfaces (5 min, error-prone)

Write the spec at `storybook/component-specs/<name>.json`. Copy the shape from a comparable existing spec. Leave `figmaComponentRef` as `null` for now (it gets filled at the end of step 5 with `"23PLdynlRYoBYQx9teoC8A#<node-id>"` — the code↔Figma link).

**Do NOT create Code Connect mappings or add a per-component entry to `src/figma/sync-ledger.json`.** Code Connect is explicitly deferred for this project (see `docs/stage1/sync-policy.md`) — the sanctioned Stage-2-complete state is `figmaComponentRef` in the spec, nothing more. The `sync-ledger.json` tracks the token artifact only, not components; it has no per-component array. Skip both rails.

Append the entry to `storybook/story-inventory.json` (**loop order** — after the previous loop's entry).

Update the **3 contract tests**. Each has its own insertion rule; this trips people every loop:

- `storybook/story-inventory-contract.test.ts` — **APPEND** (loop/file order). The array mirrors story-inventory.json.
- `storybook/proof-structure-contract.test.ts` — **INSERT alphabetically**. Read the array's existing entries by their leading string; insert between the two components whose ids straddle yours alphabetically.
- `storybook/reusable-component-promotion-contract.test.ts` — **BOTH lists**. The first array is loop/file order (append). The second (in the same test) is alphabetical (insert).

**Rule that WILL burn time if forgotten:** sort the array's existing entries by their leading string BEFORE picking an insertion anchor. If unsure, `grep -n "componentId:" <test-file>` to see the current order.

Then regenerate + verify:

```bash
pnpm govern:storybook-proof        # regenerates artifacts/storybook/proof-coverage.json
pnpm tsc --noEmit                  # must be clean
pnpm test:storybook                # all stories should pass
```

Green line: `Proof coverage: N components, N ready, 0 failing`.

### 5. Figma seed (10–20 min)

**Prerequisites:**

- The `figma-use` CLI must be installed and on `PATH`. It's an npm package (`npm install -g figma-use`), so it lives under whatever Node version was active at install time — commonly `~/.nvm/versions/node/<version>/bin/figma-use`. If `which figma-use` fails in your shell but the binary exists under nvm, either `nvm use <version>` or reinstall globally with your currently-active Node.
- Figma must be running with `--remote-debugging-port=9222`. Verify with `figma-use status`.
- Launch (only works if Figma isn't already running): `open -a Figma --args --remote-debugging-port=9222`. If Figma is already open on the wrong port, quit it first.
- **The canonical file is Collider** (`23PLdynlRYoBYQx9teoC8A`). Figma's most-recent-file default may open the wrong one — the user has an older "Collider Old" file (`BSb9QaMzwE2mv0GQ63buQK`) that sometimes claims focus. Verify: `figma-use status` should print `File: Collider`. If not, ask the user to switch tabs.
- The only page is `Primitives` (`401:1040`), canvas `Primitives Canvas` (`401:1042`).

**Placement:** find the last-seeded component's `y + height` and place the new one ~50px below. Example:

```bash
figma-use find --name "Package Info"   # → box: 480×264 at (60, 5340), so next placement is (60, ~5640)
```

**Render → bind → reparent → convert workflow:**

1. **Write JSX to `/tmp/<name>-seed.jsx`**, then `cat ... | figma-use render --stdin --x 60 --y <y>`. This lands at page root, not on the canvas.
2. **Screenshot to verify:** `figma-use export node <id> --output /tmp/<name>-v1.png` and Read the PNG.
3. **Enumerate colors for token binding:** use the `figma-use eval` tree-walker (see any recent commit; it prints `id | type | name | F=<hex> | S=<hex>` for every node with fills or strokes).
4. **Bind tokens:** `figma-use set fill <id> '$semantic/color/background/base'`, `figma-use set stroke <id> '$semantic/color/text/secondary'`, etc. Available tokens:
   - `semantic/color/background/base` (#171717) — page/card background
   - `semantic/color/background/elevated` (#2a2a2a) — nested card, badge, pill
   - `semantic/color/background/overlay` (#303030 approx) — borders, dividers, indicator strokes
   - `semantic/color/text/primary` (#ffffff) — foreground / important text
   - `semantic/color/text/secondary` (#9ca2af) — muted text, icon strokes
   - `accent/primary` (#155dfc) — active/accent surfaces
5. **Icon bindings:** bind on the **VECTOR children** (icons are `<Icon name="lucide:x">` which render as a FRAME containing 1–N VECTOR nodes). Setting the FRAME's stroke makes a visible border around the icon — WRONG. Skip icon frame fills entirely; bind icon vector strokes to `text/secondary`.
6. **Status/change-type palettes stay as raw Tailwind hex.** These palettes (green=success, red=danger, yellow=warning, blue=info, gray=neutral) are semantic to the concept, not to our design system. Don't remap them to tokens — that flattens meaning. Precedent: status-icons in [feedback_figma_icon_seeding], change-type badges in package-info.
7. **Reparent to canvas + rename + convert:**
   ```bash
   figma-use node set-parent <id> --parent 401:1042
   figma-use node move <id> --x 60 --y <y>
   figma-use eval "figma.getNodeById('<id>').name = '<Name>'; return 'ok';"
   figma-use node to-component <id>   # returns the NEW component id
   ```
8. **Update the spec:** set `figmaComponentRef` in the spec JSON to `"23PLdynlRYoBYQx9teoC8A#<component-id>"`.

**figma-use gotchas that recur:**

- **`justify="between"` / `justify="end"` on JSX may not cascade** — patch post-render with `figma-use eval "figma.getNodeById('<id>').primaryAxisAlignItems='SPACE_BETWEEN'"` (or `MAX` for end). Recurred 7+ times; live with the workaround.
- **`mt` (or ANY margin) is silently ignored in figma-use JSX.** Only paddings work (`p`/`px`/`py`/`pt`/`pr`/`pb`/`pl`). For row/column rhythm, use `gap` on the parent flex container. For a horizontal divider, use `<Frame h={1} bg="..."/>` — NOT a stroked container (that draws all 4 sides).
- **`w-full`/`flex-1`/`grow` layout-fill vendor children need visible representation.** If vendor has `<Separator />` (which is `w-full shrink-0` and stretches to fill remaining space in a flex row), your seed needs a `grow={1}` spacer element or the layout reads as broken/wrongly-aligned. Discovered in the Checkpoint v1→v2 rebuild.
- **Transparent card bg looks fine in-app (dark ambient bg) but exports invisible-white-on-white in figma-use.** Always bind an explicit `background/base` fill on the outermost card frame — even if vendor uses border-only styling. Discovered in the Agent loop.
- **Figma Text renders at unit line-height** while browsers inflate `text-sm` (14px) to ~20px. Vendor's `mt-2` (8px) that looks roomy in-browser looks cramped in a Figma export. Compensate with 12–16px gaps and slightly larger key numerals.
- **The Figma page bg is light by default** in figma-use exports; dark-only components need explicit dark card bgs to look right in the PNG. Do NOT change page bg — bind the card.
- **Vendor showcase over code fixture.** When choosing what to render in a seed, mimic the vendor's canonical example (the one on elements.ai-sdk.dev), not whatever your Story SAMPLE happens to use. The seed's job is to communicate the component's expressive range to design consumers. Discovered in the Attachments loop.
- **`<Image src="https://picsum.photos/id/N/W/H"/>` works in figma-use** — the plugin fetches the URL at render and bakes it into an image fill. Use for realistic placeholder thumbnails.

**Sanity screenshot:** always `figma-use export node <id> --output /tmp/<name>-final.png` and Read it before considering the seed done. Send it to the user for design signoff.

## Non-obvious rules (things that WILL burn time)

Ranked by recurrence.

1. **Contract test insertion order (recurs every loop).** Two arrays across three files use two different orderings. Sort the target array's existing entries by their leading string before picking an anchor.

2. **`mt` is silently ignored in figma-use JSX.** Use `gap` on parent containers. (One loop lost to this.)

3. **Registry probe BEFORE trusting inventory's scope label.** Loop #21 inventory called `controls` a "button cluster"; registry probe revealed it's a `@xyflow/react` wrapper. Cost a doc-correction commit. Inventory now includes a probed "new deps this loop" column — trust it, but verify with a `curl` if in doubt.

4. **Vendor bugs to expect:**
   - `asChild` + non-interactive element (div) breaks Radix a11y. Vendor components using this pattern need `<button>` or `<a>` as the direct asChild child. Watch for `<CollapsibleTrigger asChild><div>...` — flag and fix. (Fine when child is already a real `<button>`, as in Queue.)
   - `tool.description` in the `ai` package is now `string | ((opts) => string)`. Vendor's `{tool.description ?? 'No description'}` breaks — narrow with `typeof tool.description === 'string' ? tool.description : 'No description'`.
   - Vendor sometimes exports a component with the same name as a type it consumes. Rename the component with a `Badge`/`Row`/`Chip` suffix so the type survives (precedent: `PackageInfoChangeType` type → `PackageInfoChangeTypeBadge` component).

5. **`args` on StoryObj is typed against `meta.component`'s props, not your Demo's props.** For callback stubs, use module-scoped `fn()` + `mockClear()` in play, not `args: { onFoo: fn() }`.

6. **Tooltip stories need `<TooltipProvider>`.** Radix throws in test if no ancestor provider.
