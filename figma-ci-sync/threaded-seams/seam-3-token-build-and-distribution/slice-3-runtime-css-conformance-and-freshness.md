### S3 — Runtime CSS conformance and freshness

- **User/system value**: preserves the current runtime import path while making `src/lib/tokens/tokens.css` generated, testable, and safe for downstream adoption and CI gating.
- **Scope (in/out)**:
  - In: publishing generated CSS to `src/lib/tokens/tokens.css`; generated-file protection; deterministic rebuild proof; local freshness checker for seam-owned artifacts
  - Out: changes to `src/app/globals.css` or `.storybook/**`; CI/`justfile` enforcement; Figma sync policy
- **Acceptance criteria**:
  - `src/lib/tokens/tokens.css` is generated by the build pipeline and keeps the existing import path stable for `src/app/globals.css`.
  - The generated CSS retains the legacy variable names needed for current runtime compatibility until `SEAM-4` finishes adoption.
  - A freshness checker exists so stale artifacts can be detected locally before `SEAM-6` wires the check into CI.
- **Dependencies**: `S2`, `CT-5`, current runtime import at `src/app/globals.css`
- **Verification**: run `pnpm build:tokens` twice; confirm `src/lib/tokens/tokens.css` is unchanged on the second run; intentionally mutate a generated artifact and verify the freshness checker fails.
- **Rollout/safety**: preserve the current import path and add generated-file warnings so accidental hand edits fail early.
